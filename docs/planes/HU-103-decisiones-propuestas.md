# HU-103 · Decisiones propuestas

Distribuidora Andina y Nodo Software son empresas ficticias. Todos los datos de este documento son inventados.

HU-103 (`docs/historias/backlog-sprint-1.md:47-60`) deja abiertos varios puntos que el código tiene que resolver de alguna forma. Este documento los decide para poder implementar la historia y explica por qué. **Ninguna de estas decisiones está aprobada**: son propuestas de quien implementó la historia, pendientes de aprobación por el tech lead (P1, P4, P5, P6) y por el product owner (P2, P3). A diferencia de `HU-101-decisiones-del-equipo.md` y `HU-102-decisiones-del-equipo.md`, este archivo no recoge una revisión del tech lead; si una propuesta se aprueba o se cambia, se anota aquí con la fecha y quién la aprobó.

| Id | Tema | Propuesta | Por qué | Estado | Quién la aprueba |
|---|---|---|---|---|---|
| P1 | Dónde va el filtro | En la API: `GET /api/tenderos?vendedorId=&buscar=`. La web solo envía el texto. | La historia pide usar «el endpoint actual de tenderos» (`backlog-sprint-1.md:60`): se le agrega un parámetro, no se crea otro. Así la regla de comparación (P2) y la de longitud (P3) quedan en un solo lugar y se prueban con Supertest; la consulta sigue filtrando por la zona en SQL (CA5). Filtrar en la web también cumpliría los criterios, pero dejaría la regla solo en el navegador | Propuesta, pendiente de aprobación | Tech lead |
| P2 | Cómo se comparan mayúsculas y tildes | Se compara el texto buscado y el nombre de la tienda en minúsculas y sin marcas diacríticas: `á→a`, `ü→u` y también `ñ→n`. «dona» encuentra «Tienda Doña Rosa» y «jose» encuentra «Tienda San José». Coincide si el texto aparece en cualquier parte del nombre (CA2: «contiene») | La historia dice «sin distinguir mayúsculas, minúsculas ni tildes» (CA2) y no aclara la ñ. Se incluye porque el vendedor busca desde el celular y puede escribir sin ñ; el costo es que «pena» también encuentra «Peña» | Propuesta, pendiente de aprobación | Product owner |
| P3 | Texto de 1 o 2 caracteres y espacios | Se cuentan los caracteres después de quitar los espacios de los extremos. Con menos de 3 (incluido un texto de solo espacios) se muestra la lista completa (CA3). La API aplica la misma regla: si recibe `buscar` con menos de 3 caracteres, devuelve la lista completa y no responde 400. Los espacios interiores cuentan: «la e» encuentra «Tienda La Esquina» | CA3 fija el resultado para «menos de 3 caracteres», pero no dice si los espacios cuentan. Quitar los de los extremos sigue el criterio de R12 (`docs/modulos/tenderos.md`, §4) | Propuesta, pendiente de aprobación | Product owner |
| P4 | `buscar` que no es texto | Si `buscar` llega repetido (`?buscar=a&buscar=b`) la API responde 400 con «Revisa los datos del tendero.». No se limita la longitud: un texto de más de 100 caracteres no coincide con ninguna tienda (R11) y responde la lista vacía | No hay mensaje aprobado para este caso; se aplica D10 de HU-101 (`docs/planes/HU-101-decisiones-del-equipo.md:29`), el mensaje general para lo que no tiene mensaje propio. La web nunca envía `buscar` repetido | Propuesta, pendiente de aprobación | Tech lead |
| P5 | Cuándo llama la web a la API | La web vuelve a pedir la lista cada vez que cambia el texto efectivo (3 o más caracteres, sin los espacios de los extremos), sin esperar a que el vendedor deje de escribir, y descarta la respuesta de un texto que ya no es el actual. Mientras el texto tenga menos de 3 caracteres no vuelve a llamar. El mensaje «No hay tiendas con ese nombre en tu zona» (CA4) solo aparece con una búsqueda activa y sin resultados | La historia no habla de la frecuencia de las llamadas. Una zona tiene pocas tiendas (5 en `test-data/` para `V-101`) y la consulta es local; si la lista crece, se puede agregar una espera | Propuesta, pendiente de aprobación | Tech lead |
| P6 | Sin migración | La comparación sin tildes se hace con una función de SQLite registrada al abrir la base (`comparable`), no con una columna nueva. No se agrega migración | Una columna normalizada exigiría una migración y mantenerla al día en el registro y la edición; con pocas filas por zona no hace falta un índice | Propuesta, pendiente de aprobación | Tech lead |
